### Security

**Hard 1 — a source can inflate the run to death: decompression is synchronous, uncapped, and deliberately released from the budget before it runs.** `../permit-rulebook-data/src/watch/request.ts:164-174 @ 72b84f8`:

```
164          bytes: () => new Promise<Uint8Array>((whole, no) => {
166            const parts: Buffer[] = [];
167            res.on("data", (chunk: Buffer) => { parts.push(chunk); });
169            res.on("end", () => {
170              clearTimeout(timer);
171              try { whole(unpacked(Buffer.concat(parts), oneHeader(res.headers["content-encoding"]))); }
```

and `request.ts:103-113`: `case "gzip": case "x-gzip": return new Uint8Array(gunzipSync(bytes));` · `case "br": return new Uint8Array(brotliDecompressSync(bytes));`

What an outsider does: any of the 46 sources, or — under `anywhere` — any redirect target a `link` entry reaches, answers a few KB with `content-encoding: br` (decompressed though never asked for, by the file's own admission) or `gzip`. No `maxOutputLength`, so the default is `buffer.kMaxLength`: up to ~4 GiB allocated synchronously, on the event loop, with the budget timer already cleared one line above. Two guards that existed before are gone: `a9e6277:src/watch/fetch-source.ts:277,312` passed `signal: until` into `fetch`, and undici decompressed as a stream under that signal. Nothing now bounds either the inflated size or the time spent producing it — and a blocked event loop could not fire the timer even if it were still armed. Effect: the watch process OOMs or stalls, the pass dies, no source is reported. Live instance: none (no watchlist source sends a bomb today; every source and every `anywhere` hop can).
