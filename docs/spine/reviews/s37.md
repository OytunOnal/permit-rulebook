Scenario: `docs/spine/scenarios/s37-back-on-a-restored-record.md` (approved 2026-09-25, "onaylıyorum"; one dated correction paragraph from the build at `8d1b451`).

The build (acc8bfd, e08ab0c, 8d1b451): `src/lib/screen.ts` gains `firstHeld` — the first step of the page's list the browser holds an entry for — with `firstHeldStep(landing, current)` and `backFor(history)`; the interview's "← Back" calls `history.back()` only past `firstHeld` and otherwise steps to the previous question in place; every `pushState`/`replaceState` writes `{ step, firstHeld }`; nothing is pushed on arrival. Gates at 8d1b451 (the builder): 54 files / 772 tests, build 0 errors; four walks red on master (each landing on `/data/`).

**What the build changed from the approved words, said here so the human reads it.** Point 1 and point 4 said the page tells an arrival from a reload by the navigation's type. The build measured that a restored arrival which is then reloaded, or left and returned to, reads `reload` / `back_forward` while the browser still holds only the arrival — the approved design would have sent the screen's Back off the site in exactly those cases (confirmed independently by the Spec axis). The page therefore writes into every history entry it makes how many of its own steps the browser holds behind that entry (`{ step, held }`), reads it back on load, and **no longer reads the navigation's type at all**; an entry it cannot read — including one written by the build before this slice — counts as an outside entry, and the screen's Back steps in place, which never leaves the site. The change is strictly safer and adds no promise to "What a reader gets", but the approval was given to different words.

open with reason: src/lib/screen.ts:323-326 @ 8d1b451 — a bad or missing `firstHeld` falls toward "go back in the browser" rather than toward an arrival: a string, `{}`, a negative, `-Infinity`, `0`, or an entry written by the previous build (`{step}` only) after a reload all resolve to 0 and the screen's Back leaves the site; `NaN` sticks as `NaN`. Only a same-origin script can write `history.state`, so there is no outsider path; the real case is a reader with an arrival tab open across the deploy who reloads. Fixed in delta 1: only an integer is believed, anything else is an arrival — the safe side, because stepping in place never leaves the site.
closed: src/lib/screen.ts:323-326 — `readEntry` believes `step` and `held` only as non-negative safe integers (`src/lib/screen.ts:312,331 @ d65ff41`); eleven shapes measured as outside entries; the page reads `history.state` in exactly two places, both through `readEntry`; the navigation's type is no longer read; b0f32b8
open with reason: src/lib/screen.ts:356 @ d65ff41 — `firstHeld` is derived once, on load, and the `popstate` handler (`src/pages/index.astro:1631-1642`) reads only `step` from the popped entry and discards its `held`. So a record that SHRANK in another tab (an outside entry walked to step 8, entry `{8, held 3}`; Start over and one answer in the other tab; a reload: `firstHeld = max(0, 1 − 3) = 0`) lets three screen Backs pop entries that clamp to the same screen and the fourth call `history.back()` onto the page the reader came from — the fault this slice fixes, introduced by this delta (the round's head stayed on the site for the same steps). A record that GREW gives the opposite shape: a dead Back, or the two Backs landing on different questions. Found by the Security axis (hard) and the Spec axis (soft, the same cause). Live instance: none — two tabs on one origin, no outsider. Fixed in delta 2 with its round: `popstate` re-derives `firstHeld` from the popped entry's `held`.
