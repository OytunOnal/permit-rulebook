## What this slice is for

Everything before this was built for one reader at a time. This slice makes
it public: the dataset as an open repository other people can cite and
contribute to, the site at a name that will not change, and a page per route
that a stranger can land on from a search and trust in the first ten seconds.
It tests the three assumptions nothing else can: A2 (organic traffic comes to
open data), A7 (the gap in open work-permit data is real), A8 (a static tool
plus open data earns links). Launch is the experiment; the slice is the
apparatus.

## Design decisions this slice encodes (approved with this scenario)

1. **The name changes at the tag, in one sweep.** `visa-navigator` →
   `permit-rulebook`, `visa-rules` → `permit-rulebook-data` (not
   `permit-rules`: `permit.io` is a live developer-authorisation company and
   that slug would file the dataset under it on a repo list). The `<title>`,
   masthead, README, package names, and every user-facing string move; the
   ledgers keep their history unedited and gain one line pointing forward.
   Tagline: **"Every route, quoted and dated."** Nothing user-facing may still
   say "Visa Navigator" after the sweep — checked by grep, not by eye. **The
   design-fidelity lens reads the name against the tokens in the same slice:**
   the wordmark is set from the token type, and if the name does not sit in
   the register the stamps and copy carry, the wordmark and copy move here,
   not later.
2. **One page per route, generated from the dataset, never typed.** 23 pages
   at launch. Each renders the route's rules in the order the interview asks
   them, every threshold as the rail module — **labels stacked as a list
   below 760 px**, never overlapping — every quote with its host, its read
   date, its language tagged and a one-line frame where the source's
   notation differs from the page's (50.700 vs 50,700), the preconditions and
   readings in their blocks, the scope statement, one call to action into the
   interview pre-scoped to that route, the same country's other routes, and
   **a door to the data**: this route as JSON, the repository, the tracker.
   Every control reaches the 44 px tap minimum the tokens mandate. **A route
   page describes; it never rules on the reader** — no verdict word appears
   without answers behind it, **and no verdict colour either**: `--color-met`
   and `--color-near` appear only where the tokens define them for every
   screen (the read-date emphasis, the hero accent), never as a badge. The
   page's numbers are the dataset's numbers by construction: a test renders
   every page and compares every amount and quote to the source of truth.
3. **Coverage is a declared fact per route, said in plain words.** Three
   values, from research-01's PathWise harvest: *every deciding rule asked*
   (formerly "fully modelled" — the critique found that word to be pipeline
   vocabulary a stranger cannot parse, and its badge to overclaim), *some
   conditions stated, not asked* (the page names which, from
   `exclusions.md`), *rules quoted, nothing asked* (the route exists, its
   rules are shown, the checker does not score it). The value lives in the
   dataset, is schema-enforced, and renders as the page's scope statement and
   on the results card. Absence is not allowed: a route with no coverage
   value fails validation. **No new colour**: the scope block is ink on card.
4. **The repository goes public with what a contributor needs on day one.**
   `CONTRIBUTING.md` says how a value changes (quote + date + history, the
   watch flag, the human tier), how a route is added (the schema, the
   exclusions file, the coverage value), and what a pull request must carry.
   Issue templates carry the Steward triage labels — `bug`, `design-flaw`,
   `new-need` — and **the tracker link is on the product itself** (the route
   page's data block and the results footer), so the first stranger's
   feedback has somewhere to land. The README leads with the licence, the
   tagline and the one-line promise; NOTICE and both LICENSE files ship as
   written at the release gate.
5. **Assets someone sees in the first minute exist, and the mark is chosen.**
   The human chose the identity on 2026-09-07 from
   `docs/spine/design/s6-identity-a.html`: **the tilted "PR" stamp** — a
   square in stamp red, two mono letters filling it, rotated like the
   "Rules read" stamp — is the mark. It is the favicon at 16/32/64, the seal
   before the wordmark in the header, and the mark on the social card; no
   other drawn logo. **The social card carries no wordmark** (human,
   2026-09-07): the mark, set in the same treatment as the "Rules read" stamp
   and tilted the other way, and that stamp landing on its corner, are the
   card's identity; the name travels in the link's title and description. The wordmark is set from the token type and fits at
   390 px; the social card — OG image and meta on every page — shows title,
   tagline and the mark when a link is pasted into a preview. Accepted cost,
   stated: at 16 px the tilt costs a little sharpness. The identity, like any
   new screen, goes through the isolated critique before the tag.
6. **Deploy is static, on GitHub Pages, from the same repository the cron
   runs in.** Cheap default, surfaced: one vendor, zero cost, the daily watch
   already lives in GitHub Actions, and a static site needs nothing else. The
   custom domain is bound at the tag. Cost: no headers we control and no
   server-side anything — which this product has promised never to need. If a
   CSP or a redirect ever matters, Cloudflare Pages is the move and the
   DECISIONS entry names it.
7. **The daily watch goes live and its first flag is walked by hand.** The
   cron that has been dry-running since v0.6 starts filing issues **before the
   announcement**. The first real flag — whatever it is — is read by the human
   against the source before anyone edits a value, so the loop is exercised
   once with a person in it.
8. **The phone walk happens on the preview, before any announcement.** The
   deploy preview URL is the first thing a real handset sees; the launch post
   is written only after that walk passes.
9. **The disclaimer is the launch's legal wording, and it is one sentence
   everywhere.** The IRCC-style text already on the site becomes the single
   source for the route pages, the README and the launch post — "makes no
   immigration decision and authorities won't consider these results". A1's
   condition (no advice, no verdict on the person) is satisfied by the copy,
   and the route pages add "this page describes the rules; it does not decide
   on you".
10. **The announcement is the README, told once.** A Show HN and the
    repository README carry the same claim in the same words: an open, dated,
    source-quoted work-permit ruleset for four countries, 23 routes, every
    value with its official sentence and the day it was read, checked daily.
    No promise the product does not keep, no count the dataset does not hold.
    A GitHub Sponsors link, small, beside the licence.
11. **The first 48 hours are named before the link goes out.** Three lines in
    STATUS.md's expected-from-you, written before the announcement: what to
    watch (the tracker, the watch flags, the HN thread), where, and what would
    make us pull the post (a wrong verdict reported and confirmed; a source
    flag that reveals a stale value on a live page; a legal objection to a
    quote). Written first, not after.
12. **Dates are one format, and the stamp is the newest read date on the
    page.** ISO everywhere a date is printed; the "Rules read" stamp equals
    the latest read date among the page's quotes, so a reader can derive it
    from the lines below.
13. **v1 is stamped only after the isolated critique.** The full walk by the
    critique agent — every persona, every lens, RUBRIC 1.2, on the deployed
    preview — runs before the tag. Blockers clear or the tag waits; scores are
    recorded, not gated on.

## Seed data

The dataset as of s5f real-green: 23 routes, every value and sentence sourced.
The coverage value for each route is authored in this slice from
`exclusions.md` and the readings — a curation pass, with the reason for each
written beside it.

## Steps

1. **A stranger lands cold.** Open `/germany/eu-blue-card-general` with no
   history, as someone who searched "Germany Blue Card salary 2026". In ten
   seconds they can answer: what is the threshold, where does that number come
   from, when was it last checked, and what do I do next. Read the page aloud
   as prose; no line needs the interview to make sense; no abbreviation goes
   unexplained on first use.
2. **The page is the dataset.** Change one threshold in a local copy of the
   dataset, rebuild: the page changes and the test that compares every page's
   amounts and quotes to the dataset passes only when they agree.
3. **No page rules on the reader, in word or colour.** Grep every generated
   route page for the verdict vocabulary — *criteria met*, *within reach*,
   *not yet*, *you qualify* — and find none; scan every page's computed
   styles for `--color-met` and `--color-near` outside the read-date emphasis
   and the hero accent, and find none.
4. **The coverage value is honest.** Open the three routes with the most
   exclusions (`nl-orientation-year`, `es-highly-qualified`, `de-chancenkarte`):
   each says "some conditions stated, not asked" with the excluded limbs
   named; a route with nothing excluded says every deciding rule is asked;
   removing a route's value from the dataset fails the build.
5. **The name is gone.** After the sweep, `git grep -i "visa navigator\|visa-navigator"`
   over both repositories returns only ledger history and the one forwarding
   line. The `<title>`, the masthead, the README and the launch post say
   Permit Rulebook. The old repository names redirect. The wordmark fits at
   390 px and reads as one product with the stamps.
6. **The first minute's assets.** The tab shows a favicon; the announcement
   link pasted into a preview tool shows title, tagline and image; the
   README's first screen carries licence, tagline and promise.
7. **Phone (mandatory, real handset, on the preview).** The interview end to
   end and one route page: nothing overflows 390 px, every tap target
   measures at least 44 px, the rail's labels are a readable list, the scope
   statement reads without zooming.
8. **The watch files its first issue with a person watching, before the
   post.** Trigger or wait for the first live flag; the human reads the
   flagged source against the quote; the outcome — value changed, false
   alarm, or source moved — is recorded in DECISIONS with what the flag said
   and what was true.
9. **The way back in works.** From a route page and from the results footer,
   the tracker link opens the repository's issue form with the three labels
   available; a test issue filed from it lands labelled.
10. **Edge profile (mandatory).** A stranger who lands on a route page for a
    country where they hold a passport that needs no permit (an Irish reader
    on a German page): the page says who it is for before the first rule, and
    the call to action leads to the notice, not to a rejection. And the
    weakest profile through the interview from a route page's call to action:
    the pre-scoped route appears first in the results and every behaviour
    from s5d and s5e holds.
11. **The 48-hour lines exist before the link goes out.** STATUS.md carries
    the three lines; the announcement is not posted until they do.
12. **The isolated critique clears.** The critique agent walks the deployed
    preview; its blockers are fixed and re-verified; its scores are recorded
    with the delta from v0.7's isolated run.
13. **Regression.** All suites green in both repositories; watch coverage both
    ways; quote fidelity `ok`; `human_tier: 0`; `astro check` zero errors on
    24 pages.

## Invariants (property tests)

- **Every amount and every quote on every generated page equals the dataset's**,
  over all routes — the page cannot drift from the source of truth.
- **No generated page contains a verdict word, and no element outside the
  read-date emphasis and the hero accent resolves to a verdict colour**, over
  all routes.
- **Every route carries exactly one coverage value and its stated exclusions
  match `exclusions.md`**, over all routes.
- **Every interactive element on every generated page measures at least the
  tap minimum at 390 px**, over all routes — the v0.7 finding, made permanent.
- **No user-facing string in either repository contains the working name**
  after the sweep — a grep-shaped test that stays in the suite.
- Everything from the existing suites, re-run.

## De-mock births

- The coverage value is authored by hand at launch; a derived check that the
  authored value agrees with the route's actual criteria and exclusions is a
  v1.x candidate.
- The launch tests A2/A7/A8 for real; each gets a `slice-verified` or
  `refuted` line in `assumptions.md` thirty days after the announcement, with
  the number that decided it.
- The hero accent's reuse of `--color-near` on a non-ruling page is a token
  split waiting for a design-system entry — recorded, not done here.
