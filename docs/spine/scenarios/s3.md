# s3 — "Gap analysis on the results screen" · Acceptance scenario

Status: APPROVED — human, 2026-09-02 (the scenario + the screen mock together).
Screen mock: `docs/spine/design/s3-results.html` (inside the token set).

## Seed data

The v0.2 dataset (DE 8 routes) + an optional `learn` source on the field definitions
(a schema extension): `recognition_de` → the official URL of the Anabin database,
`occupation_shortage` → the official list of §18g shortage occupation groups.
(Curation: two official URLs, no quote needed — an information link, not a value.)

## Steps

1. **Grouped result:** the screen in three sections — the headings "OPEN —
   criteria met (n)" / "WITHIN REACH (n)" / "NOT YET (n)" + a summary strip at
   the very top ("2 open · 1 within reach · 5 not yet — 1 has an open
   unknown"); the numbers are exactly consistent with the profile.
2. **Compact hold rows:** NOT YET routes are a single line (name + a one-sentence
   reason); clicking opens the detail. Met/near cards stay in full view.
3. **"I don't know" → learn box:** on a route that has a field answered "I
   don't know", a blue box: "You can find out yourself: … [official link] ↗" —
   the link comes from the `learn` field in the dataset, it is not written into
   the UI by hand; when a new country/field is added it appears by itself.
4. **Gap regression:** on the near card the rail + the "up to €X" gap note and
   the points-gap behaviour exactly as before (from S2).
5. **Flow regression:** the engineer persona still finishes in 7 questions;
   the explorer persona's result falls correctly into the new groups
   (Chancenkarte → within reach, with the points breakdown).
6. **Schema regression:** the `learn` field was added to the schema; a value
   without a quote/date still cannot break the build.
