## Design decisions this slice encodes (approved with this scenario)

1. **Destination question** opens the flow: "Where are you looking?" —
   DE / FR / ES / NL / "anywhere in these four". Attribute kind (no leverage
   rows like "with a different destination…"); every route carries a
   destination criterion. Choosing one country means the other countries'
   questions are never asked.
2. **Country-scoped fields**: recognition, situation-details and other
   country-specific declarations exist per country and are asked only while
   that country's routes are alive (existing pruning does the work).
   Shared facts (citizenship, age, experience, languages) stay single fields.
3. **NL salaries are monthly** (that's how IND publishes them): a separate
   monthly-salary field with its own bands; no unit conversion — provenance
   quotes stay verbatim.
4. **Per-country exclusion lists** are committed artifacts
   (`data/exclusions.md`): every route we deliberately did NOT model, with a
   reason (seasonal, seafarer, discretionary §21-style, post-study…).
5. **Country sections are collapsible** (human request at the boundary):
   sections with at least one open/within-reach card come expanded; all-not-
   yet countries come collapsed, their header tally still visible.
6. **Leverage stays, per country** (human request at the boundary): unlock
   steps render inside the country section whose routes they open; a step
   opening routes in several countries appears in each section with that
   section's routes only. A collapsed country whose section contains unlock
   steps says so in its header tally ("2 not yet · 1 unlocking step") — a
   closed panel must never hide hope. **Wording is conditional** (human
   catch): "would be met" / "would come within reach", never "criteria met" —
   these are futures, not achievements. (Fixed in the live v0.5 UI in the
   same change.)

## Seed data

already scouted (FR: service-public F16922 family; ES: Ley 14/2013 / UGE +

## Steps

1. **Single-destination regression**: a DE-only engineer answers ≤8 questions
   and gets exactly today's v0.6 result — adding three countries costs a
   DE user at most the one destination question.
2. **NL flow**: destination=NL, an offer-holder engineer → HSM met on the
   monthly threshold (quote from ind.nl with validity window), NL Blue Card
   evaluated on its own monthly band set; no German questions ever asked.
3. **"Anywhere" explorer**: the mock's screen — collapsible country sections
   (design-F header pattern; hopeful countries expanded, all-not-yet ones
   collapsed) each with status groups inside, one overall summary strip;
   counts consistent per country and in total.
4. **Edge profile (mandatory)**: "anywhere" + weakest answers (no language,
   unknown recognitions, low funds) completes the full interview and every
   country resolves to honest not-yet/within-reach states with field-named
   gaps and learn links where defined; leverage steps stay provable-only and
   render per country (e.g. "With a French employment contract → Talent —
   met" inside the France section; "With German B2 → Chancenkarte — met"
   inside Germany's), with collapsed-country tallies carrying the
   "unlocking step" hint.
5. **ES human tier end to end**: the ES threshold values enter from the UGE
   PDF path (human-read tier); simulate a byte change → "changed (human must
   read)" flag; no value is ever machine-extracted from the PDF.
6. **Curation honesty**: agent-drafted values enter with a per-country
   human verification checklist (like s2) — real-green requires your VPN
   pass over FR/ES/NL sources; exclusion lists reviewed in the same pass.
7. **Regression**: all existing tests stay green; property suites (which are
   dataset-agnostic) now sweep the 4-country rule space unchanged —
   termination, status consistency, unlock soundness/completeness,
   end-state stability.
